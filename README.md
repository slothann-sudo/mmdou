# 有人车—多无人机协同前出侦察 · 注意力分配实验原型

独立运行的 React + TypeScript + React Router + Vite 网页应用。首页集中展示入口与条件配置；实验在独立路由中进行。第二阶段已实现 PT-01 动态目标跟踪训练和 PT-02 UAV 任务冲突判读训练。首页正式实验配置采用“实验一主任务支持 → 实验二次任务介入”的分层结构；实验一的 N0–N5 已接入同屏主次任务，实验二仍是原型框架。

## 安装与本地启动

需要 Node.js 20.19+ 或 22.12+。在项目目录执行：

```bash
npm install
npm run dev
```

终端会显示本地地址，在普通浏览器中打开即可。应用不依赖 ChatGPT 界面或其专用 API。

如果只需打开现有本地预览，可双击项目根目录的 `start-local.cmd`。它会在预览服务未运行时启动服务并打开浏览器。电脑重启后需要再次双击。

## 生产构建

```bash
npm run build
npm run preview
```

构建输出位于 `dist/`。部署到普通静态 Web 服务时，应将未知路径回退到 `index.html`，这样直接打开或刷新独立实验路由仍可访问。当前 Sites 配置已启用单页应用回退。

## 路由

| 路径 | 页面 |
| --- | --- |
| `/` | 实验首页：预实验入口、两阶段正式条件配置、结果导出 |
| `/pretest/main-task` | PT-01 主任务预实验 |
| `/pretest/sub-task` | PT-02 次任务预实验 |
| `/pretest/combined-task` | PT-03 主次任务组合预实验 |
| `/pretest/support` | PT-04 注意再分配支持预实验 |
| `/formal/run` | 独立正式实验运行页 |

首页不以弹窗、抽屉、局部展开或 iframe 执行实验。所有“进入”操作都通过 React Router 跳转。

## 数据保存

每次打开或刷新网页都会开始一轮新的被试会话：被试编号、预实验进度、条件选择与正式结果都从空状态开始，数据只保存在当前页面内存中。应用不从浏览器存储恢复历史数据，并会定向移除旧版本使用的 `attention-platform-single-page-v1` 键。同一页面会话内可连续完成多个正式条件；首页结果区仅列出当前被试的记录，可单条或合并导出 CSV。同一被试重复完成同一阶段和条件时，最新记录覆盖旧记录。刷新或关闭前须手动导出；有未导出的正式结果时，浏览器会给出原生离开提示。预实验数据不进入正式实验结果。实验一 N0–N5 记录主任务选择、正确率、选择用时，以及 UAV 判断和反应时；N1、N4 和 N5 还保存迁移前标记，N3、N4 和 N5 还保存全部目标的历史位置与次任务占用期间的运动路径。

实验一只配置 N0–N5 主任务支持，次任务使用固定基础呈现；实验二只配置直接介入或注意引导，主任务支持来源标记为“实验一筛选结果”。当前原型尚未计算或接入真实筛选结果，也没有把提示模态作为独立自变量。

实验一 N0 运行页分为顶部状态栏、中间固定 16:9 实验画布和底部控制栏。画布左侧约 72% 为 MOT，右侧约 28% 常驻显示三架 UAV 的电量、信号、状态、任务、传感器和链路。单轮先用 3 秒静止高亮与倒计时记忆初始目标，再进行 30 秒持续跟踪；目标以较慢的直线运动并在边界反弹。跟踪开始后 8–16 秒之间随机触发一题限时 8 秒的 UAV 判断，单击右侧方案卡即记录，短暂反馈后恢复 UAV 状态信息，MOT 始终持续运动。临近结束时只提示一次，跟踪结束后目标停止；选中最初标记的 4 个目标后可修改选择，点击“确认选择”锁定，再点击“结束实验”记录正式结果。N0 不提供主任务辅助线索。

实验一 N1 复用 N0 的画布、MOT 参数、题目和最终选择流程。左下角固定显示标记工具；次任务出现前不可用，出现后可点击，但外观保持默认。只有被试点击后工具才亮起并进入标记模式。正式判读内容在次任务触发时直接出现在右侧；被试可立即单击候选方案，也可先标记运动目标。标记采用点击选中、再次点击取消，最多保留 4 个；选满后仍可取消并更换。被试可直接点击右侧方案完成判断，也可再次点击工具退出标记模式；最多 6 秒后也会自动退出，并受主任务剩余时长约束。标记会随目标继续移动。标记期间次任务判读计时暂缓，MOT 持续运动。N1 的标记使用情况与所标目标随正式结果保存。

实验一 N2 复用 N0 的 MOT、UAV 状态区、随机触发时机、判读题目、限时与最终选择流程。次任务到达后，UAV 状态区只标出任务来源，实际判读选项进入 MOT 区域右侧的紧凑半透明任务卡。单击方案即记录；答题或超时后任务卡在约 0.3 秒内淡出。MOT 目标仍以原尺寸、速度和坐标持续运动，不增加编号、轨迹或标记。

实验一 N3 沿用 N0 的界面、运动参数、次任务和最终选择流程。随机次任务到达时，系统只在后台保存全部 10 个目标的历史位置，并约每 0.1 秒采样一次位置；答题结束或超时、右侧任务层关闭后，原 MOT 画面叠加空心历史锚点、由淡到清晰的细虚线运动路径，以及当前实心目标的轻量外圈。历史锚点同时轻微强调一次。前 4 秒保持稳定，第 4–6 秒平滑淡出，MOT 全程继续运动；所有目标使用相同规则，不区分最初应追踪的 4 个目标。

实验一 N4 在同一运行画布中连续复用 N1、N2、N3：随机次任务触发时，边缘嵌入式判读 HUD 直接出现在 MOT 区域，标记工具同时可用。被试主动标记的目标在任务处理、N3 回归及后续 MOT 阶段持续跟随小球，直到本轮实验结束；最终选择的目标暂时以最终选择样式覆盖标记，取消选择后原标记恢复。历史锚点和虚线运动路径仍在约 6 秒后淡出。HUD 采用窄幅半透明布局，让运动目标仍可见。内嵌任务出现时间、题目、判读限时与 MOT 总时长沿用 N0。N4 的正式记录保存标记使用情况及回归轨迹。

实验一 N5 组合 N1 与 N3：突发任务按 N0 方式直接出现在右侧 UAV 区域，不使用 N2 内嵌 HUD。标记工具仅在任务出现后可用，被试主动标记的目标持续保留到本轮结束；次任务作答或超时后，全部目标的历史锚点与细虚线轨迹在 MOT 区域显示约 6 秒，N1 标记同时保留。最终选择样式优先于标记，取消选择后恢复标记。结果记录同时保存 N1 标记和 N3 回归信息，条件为 N5。

## 第二阶段训练

- PT-01：默认 10 个动态目标、4 个重点目标；5 秒准备、5 秒高亮、30 秒跟踪，结束后选择目标并查看训练反馈。运动引擎使用可编辑随机种子，支持暂停、继续、重置和下一轮。
- PT-02：默认 3 个候选方案、5 项指标、每题 8 秒、5 道中等难度题。题库独立存放，支持倒计时、超时、反馈、暂停和下一题。
- 训练算法与 UI 分离，相关模块位于 `src/pretests/`。数据与正式实验记录隔离。

使用 Node.js 24 可运行核心逻辑检查：`npm test`。

浏览器数据不是正式研究数据：清理站点数据、更换浏览器或设备会失去这些本地记录。真实刺激、采集、指标计算及正式持久化尚未实现。
